1What an agent is

Anthropic drew a line between two things people call "agents". Read it twice, because the whole session sits on this line.

"Workflows are systems where LLMs and tools are orchestrated through predefined code paths."Anthropic, Building effective agents
"Agents, on the other hand, are systems where LLMs dynamically direct their own processes and tool usage, maintaining control over how they accomplish tasks."Anthropic, Building effective agents

Both start from the same building block. Anthropic calls it the augmented LLM: a model with retrieval, tools and memory attached.

And the autonomous agent is that box in a loop with its environment. A human hands over a task, the model acts, reads what happened, and goes again until it stops.

Anthropic's own advice, verbatim: "we recommend finding the simplest solution possible, and only increasing complexity when needed. This might mean not building agentic systems at all." Keep this in your pocket for the moment someone wants six agents for a one-file change.

Before you build any subagent, see the loop you are already inside. The docs describe one turn like this:

"When you give Claude a task, it works through three phases: gather context, take action, and verify results. These phases blend together."How Claude Code works

3What a subagent is

"Each subagent runs in its own context window with a custom system prompt, specific tool access, and independent permissions. When Claude encounters a task that matches a subagent's description, it delegates to that subagent, which works independently and returns results."Create custom subagents

The docs list five things a subagent buys you. This is the slide to remember when someone asks "why not just prompt harder".

01

Preserve context

"by keeping exploration and implementation out of your main conversation"

02

Enforce constraints

"by limiting which tools a subagent can use"

03

Reuse configurations

"across projects with user-level subagents"

04

Specialize behavior

"with focused system prompts for specific domains"

05

Control costs

"by routing tasks to faster, cheaper models like Haiku"

4The one idea that matters: its own context

Everything else on this page follows from this diagram. Your main conversation has one context window. Every file you read, every log you print, sits in it until the session compacts. A subagent gets a fresh window, does the messy work there, and hands back only the summary.

The line people miss, from the docs: "Each subagent starts with a fresh, isolated context window. It doesn't see your conversation history, the skills you've already invoked, or the files Claude has already read." So a subagent is not a helper who was in the meeting. It is a contractor who gets a brief.

5A subagent is a Markdown file

No SDK, no code. One file in .claude/agents/. The top half is YAML frontmatter, the bottom half is plain text that becomes the subagent's system prompt.

Where the file lives decides who gets it

Location Scope Priority How to create
Managed settings Organization-wide 1 (highest) Deployed via managed settings
--agents CLI flag Current session 2 Pass JSON when launching Claude Code
.claude/agents/ Current project 3 Ask Claude, or create the file manually
~/.claude/agents/ All your projects 4 Ask Claude, or create the file manually
Plugin's agents/ directory Where plugin is enabled 5 (lowest) Installed with plugins

Table reproduced from the docs. For a team, use .claude/agents/ and commit it: "Check them into version control so your team can use and improve them collaboratively."

6The fields, one by one

All 18 supported frontmatter fields, in the order the docs list them. Two are required. For a first agent you will set five. The rest exist so you know what the dial is called when you need it.

Field Required What the docs say it does What to put for a PM reader agent
name Yes "Unique identifier using lowercase letters and hyphens." Names can't contain :. The filename doesn't have to match. survey-reader
description Yes "When Claude should delegate to this subagent" "Use when..." plus two example questions a user would type
tools No "Inherits every tool available to subagents if omitted." If no entry resolves to a tool, the subagent fails to launch. Read, Glob. A reader never needs Write.
disallowedTools No "Tools to deny, removed from inherited or specified list." An entry with a specifier such as Bash(git push *) still removes the whole tool. Use when you want most tools minus a few
model No sonnet, opus, haiku, fable, a full ID, or inherit sonnet for reading, haiku for search
permissionMode No default, acceptEdits, auto, dontAsk, bypassPermissions, plan, or manual as an alias for default. Ignored for plugin subagents. Leave default
maxTurns No "Maximum number of agentic turns before the subagent stops." Output comes back marked partial and Claude can resume it. A cap for anything that could loop
skills No "Skills to preload into the subagent's context at startup. The full skill content is injected, not only the description." Leave empty unless the skill is small. Full content means full cost.
mcpServers No "MCP servers available to this subagent." A server name already configured, or an inline definition. Ignored for plugin subagents. Only if the agent needs Slack, Jira or similar
hooks No "Lifecycle hooks scoped to this subagent." Ignored for plugin subagents. Later. A PreToolUse guard once the agent is trusted
memory No "user, project, or local. Enables cross-session learning" project, so the team shares what it learns
background No "Set to true to keep this subagent in the background even when Claude asks to run it in the foreground." Leave unset
omitClaudeMd No "Set to true to launch this subagent without the user, project, and local CLAUDE.md files". For subagents that take everything from the delegation message. Leave unset. A PM agent wants the company context in CLAUDE.md.
effort No "Effort level when this subagent is active. Overrides the session effort level." Options: low, medium, high, xhigh, max; available levels depend on the model. Leave unset, or low for a pure reader
isolation No "Set to worktree to run the subagent in a temporary git worktree", branched from your default branch. Cleaned up automatically if the subagent makes no changes. Only for agents that write code
color No "Display color for the subagent in the task list and transcript." Accepts red, blue, green, yellow, purple, orange, pink, or cyan. One colour per role so you can read a fan-out at a glance
initialPrompt No "Auto-submitted as the first user turn when this agent runs as the main session agent (via --agent or the agent setting)." Commands and skills are processed. Only when the agent is the whole session
experimental No "Map of experimental options. Set its cacheTtl key to 5m or 1h to choose the prompt cache lifetime for this subagent's requests". Requires v2.1.248 or later. Write cacheTtl inside the map, not at the top level. Leave unset

Memory, the field that makes it better every week

USER

~/.claude/agent-memory/<name>/

"the subagent should remember learnings across all projects"

PROJECT

.claude/agent-memory/<name>/

"the subagent's knowledge is project-specific and shareable via version control"

LOCAL

.claude/agent-memory-local/<name>/

"project-specific but shouldn't be checked into version control"

How much it remembers, from the docs: "The subagent's system prompt also includes the first 200 lines or 25KB of MEMORY.md in the memory directory, whichever comes first". Seed MEMORY.md with a starting checklist, and tell the agent in its body to update it after every run.

7The three built in

You already use subagents without writing any. Claude Code ships three and delegates to them on its own.

EXPLORE

Search without changing

"Claude delegates to Explore when it needs to search or understand a codebase without making changes. This keeps exploration results out of your main conversation context." Thoroughness: quick, medium, very thorough.

PLAN

Research in plan mode

"When you're in plan mode and Claude needs to understand your codebase, it delegates research to the Plan subagent so that exploration output stays in a separate context window".

GENERAL-PURPOSE

Explore and modify

"Claude delegates to general-purpose when the task requires both exploration and modification, complex reasoning to interpret results, or multiple dependent steps."

One detail worth knowing: "Explore and Plan skip your CLAUDE.md files and the parent session's git status to keep research fast and inexpensive. Every other built-in and custom subagent loads both". Your custom agent sees CLAUDE.md, the two fast ones do not.

8Five patterns, with Anthropic's diagrams

Anthropic's article names the patterns that work in production. Each one maps to a real agent in this repo, so you can open the file next to the picture.

Pattern 1. Routing

IN THIS REPO

pm-request-router

Takes a vague PM ask, classifies it as PRD, COMPETITOR, CHURN or UNCLEAR, and dispatches the matching specialist. Its only tool is Agent. It never answers the request itself, which is exactly the router box in the picture.

Pattern 2. Parallelization

IN THIS REPO

feedback-triangulator

Fans out three workers in parallel (interviews, survey, churn), then keeps only issues corroborated by two or more sources. The docs call this "Run parallel research": "Each subagent explores its area independently, then Claude synthesizes the findings."

Pattern 3. Orchestrator-workers

IN THIS REPO

interview-insight-synthesizer

A four-stage pipeline over 07-user-interviews/: extract pains, cluster into themes, rank, write the brief, with a quality gate between stages. The difference from parallelization: the orchestrator decides the split at run time, it is not fixed in advance.

Pattern 4. Evaluator-optimizer

IN THIS REPO

senior-code-reviewer

The evaluator box. It sees the artifact only, never the builder's reasoning, and reports with file and line. Give it Write access and it will quietly fix things instead of reporting them, and then you have no review.

Pattern 5. Prompt chaining

FROM THE DOCS

"Chain subagents"

"For multi-step workflows, ask Claude to use subagents in sequence. Each subagent completes its task and returns results to Claude, which then passes relevant context to the next subagent." Example prompt from the docs: Use the code-reviewer subagent to find performance issues, then use the optimizer subagent to fix them.

10Build one in 10 minutes

  1. Ask Claude to write the file. The docs recommend this over hand-writing: "Ask Claude, or create the file manually". Prompt: "Create a subagent at .claude/agents/survey-reader.md. Tools Read and Glob only, model sonnet, memory project. It reads 06-user-feedback/ and reports churn drivers with file and line for every quote. Write a description that starts with 'Use when' and includes two example questions."
  2. Open the file and check the frontmatter. The docs say to do exactly this: "Open the file and confirm the frontmatter matches what you asked for." Fix by hand if the tools list is wider than you asked.
  3. Trigger it. Ask: "What does the Q1 survey say about action items?" You should see Claude delegate to survey-reader and a cited answer come back.
  4. If it does not fire, force it once, then fix the description. The docs give three escalation levels: name it in the prompt, @-mention it ("guarantees the subagent runs for one task"), or make it the whole session with --agent. But an agent you must @-mention every time has a broken description. Rewrite it with the words a user actually types.
  5. Calibrate. Change the description to "Helps with feedback.", ask the same question, watch it not fire. Put the good description back. Now you know what the field does.
  6. Seed its memory. Create .claude/agent-memory/survey-reader/MEMORY.md with three lines: what the survey file looks like, the one trap you already know about (the survey is a Q1 artifact, not "recent"), and an instruction to append a lesson after every run.
Done means: the file exists, the agent fires on a natural question without an @-mention, the answer cites file and line, and the memory folder has a MEMORY.md. Renders is not done.

11Where it breaks

BREAK 1

Vague description, never fires

"Helps with feedback." competes with every other agent and loses. Claude reads the description to decide. Give it the trigger words and two examples. The docs also note the whole set of descriptions has a 15,000-token limit before a warning fires, so brief and precise beats long and generic.

BREAK 2

Too many tools, silent fixes

A reviewer with Write and Edit will change the file and report "fixed" instead of reporting the defect. Then nobody reviewed anything. Readers get Read and Glob. Reviewers get read tools plus Bash for checks, and a body that says report, never edit.

BREAK 3

It cannot see your conversation

You spent ten minutes explaining the context, then delegated. The subagent got a fresh window and none of that. "Claude composes a delegation message that summarizes the task, and the subagent works from there." Put the standing context in the body of the file, not in chat.

BREAK 4

Self-marked homework

One agent builds and reviews its own work. It passes itself every time. The evaluator must be a separate agent that sees the artifact only. This is why the reviewer in this repo is its own file.

BREAK 5

Using a subagent for a chat question

The docs are direct: for "a question about something already in your conversation, use /btw instead of a subagent. It sees your full context but has no tool access". And for a quick targeted change, stay in the main conversation. A subagent "starts fresh and may need time to gather context".

BREAK 6

Treating the report as proof

An agent's report is a claim about what it did, not evidence of the current state of disk. Open the artifact it says it wrote. Count the citations it says it added. A reviewer that reports zero defects is presumed not to have run.
