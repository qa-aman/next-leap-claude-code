1What a dynamic workflow is

"A dynamic workflow is a JavaScript script that orchestrates many subagents at once. Claude writes the script for the task you describe, and a runtime executes it in the background while your session stays responsive."Orchestrate subagents at scale with dynamic workflows

Three words in that sentence carry the whole idea.

SCRIPT

It is a file, not a conversation

The orchestration is code you can read, diff, edit, rerun and share. Compare a subagent, where the worker is a file but the sequence lives only in Claude's turn-by-turn judgement.

CLAUDE WRITES IT

You describe the task, not the loop

You never write JavaScript. You say "use a workflow to..." and Claude drafts the script, shows you the phases, and asks before running.

BACKGROUND

Your session stays free

"The workflow runtime executes the script in an isolated environment, separate from your conversation. Intermediate results stay in script variables instead of landing in Claude's context."

When to reach for one, in the docs' words: "when a task needs more agents than one conversation can coordinate, or when you want the orchestration codified as a script you can read and rerun. Examples include a codebase-wide bug sweep, a 500-file migration, a research question that needs sources cross-checked against each other, and a hard plan worth drafting from several independent angles before you commit to one."
Availability: "Dynamic workflows are available on all paid plans, with Anthropic API access, and on Amazon Bedrock, Google Cloud's Agent Platform, and Microsoft Foundry. On Pro, turn them on from the Dynamic workflows row in /config." Do this before class starts.

3The patterns a workflow codifies

A workflow does not invent new patterns. It takes the ones from Anthropic's "Building effective agents" and turns them into code you can rerun. The docs say so directly: "Moving the plan into code also lets a workflow apply a repeatable quality pattern, not just run more agents: it can have independent agents adversarially review each other's findings before they're reported, or draft a plan from several angles and weigh them against each other".

Parallelization: many readers at once

IN A WORKFLOW

Phase 1 of the churn run

Three readers, one per source folder, all launched together. The script waits for all of them before the next phase starts. Up to 16 agents run at once on a normal machine.

Orchestrator-workers: one agent per item, decided at run time

IN A WORKFLOW

One agent per item, discovered at run time

The script asks one agent to list the files or the drivers, then runs one agent per item on that list. The split is decided by the first agent's output, exactly the orchestrator box in the picture. This is how the docs' route-audit example works: list the routes, then audit each one.

Evaluator-optimizer becomes a verify phase

IN A WORKFLOW

Phase 3 of the churn run, and /deep-research

A fresh agent per finding, told to refute it against the source. The bundled /deep-research workflow does this at scale: it "votes on each claim, and returns a cited report with claims that didn't survive cross-checking filtered out." The evaluator never sees the generator's reasoning, only the claim and the source.

4Four ways to start one

A

Say it in your own words

"use a workflow" or "run a workflow" in your prompt. "Claude treats a direct request as the same opt-in." This is what the workshop uses.

B

The keyword ultracode

ultracode: audit every API endpoint under src/routes/ for missing auth checks. "Claude Code highlights the keyword in your input and Claude writes a workflow script for the task instead of working through it turn by turn." Dismiss with Option+W on Mac.

C

/effort ultracode

"Claude plans a workflow for each substantive task instead of waiting for you to ask." Costs more on everything. "Drop back with /effort high when you return to routine work."

D

A bundled or saved command

/deep-research <question> ships with Claude Code. Anything you save yourself appears in / autocomplete the same way and can take input through args.

Where the keyword works, from the docs: "The keyword is an opt-in only in a prompt you type yourself". It does not start a workflow from a -p prompt, a scheduled task prompt, or "a webhook payload or pull request comment relayed into the conversation". A saved command works from all of those.

5The life of one run

"Every run writes its script to a file under your session's directory in ~/.claude/projects/. Claude receives the path when the run starts, so you can ask for it." So even before you save it as a command, the script exists on disk and you can diff two runs.

6Approve the plan

THE PROMPT SHOWS

Four options

  1. Yes, run it
  2. Yes, and don't ask again for name in path. Offered for a bundled, saved or plugin workflow, "not for a script Claude wrote for the current task."
  3. View raw script
  4. No

"Ctrl+G opens the script in your editor. Tab lets you adjust the prompt before the run starts."

WHEN YOU ARE ASKED

Depends on permission mode

ModePrompted
AutoFirst launch only. Skipped entirely when ultracode is on.
Manual, accept editsEvery run, unless you chose "don't ask again" for that workflow in this project
Bypass permissionsNever. The run starts immediately.
claude -p, Agent SDKNever. Deny rules, ask rules and dontAsk still apply to the launch.
The agents inside still obey your rules: "The subagents the workflow spawns use your permission rules". "To avoid prompts on a long run, add the tools the agents need to your allow rules before starting." A run that stops every 40 seconds for a Read prompt is a run you forgot to prepare.

WHAT TO LOOK AT IN CLASS

Drill into one verifier

"The agent detail lists the agent's prompt, its recent tool calls, and its result." Open one Verify-phase agent, read its prompt out loud, and show that it was told to refute, not confirm. Then show the token count next to it. That number is the price of the adversary you never had before.

Also on the task panel below the input box: "a one-line progress summary appears there while the run is going."

8Save it as a command

  1. Open /workflows, select the run, press s. "When Claude writes a workflow for a task you'll repeat, you can save that run's script as a command."
  2. Tab picks the location. ".claude/workflows/ in your project: shared with everyone who clones the repo" or "~/.claude/workflows/ in your home directory: available in every project, visible only to you." For a team artifact, project.
  3. Run it as /<name> next time. "The workflow runs as /<name> in future sessions from either location." If a project and a personal workflow share a name, the project one runs.
  4. Pass input with args. Example from the docs: Run /triage-issues on issues 1024, 1025, and 1030. "Claude passes the list as structured data".
  5. Edit it later the safe way. "Before you edit or ask, run the /workflow-authoring bundled skill to load the script-writing reference Claude works from." Then /reload-skills and run /<name> again.
  6. Share it beyond one repo with a plugin. "Place the script in a workflows/ directory at the plugin root". It runs as /plugin-name:workflow-name.
Why this is the point of the word "dynamic": the orchestration is now a file in git, next to your agents. A review you run on every branch, a triage you run on every new batch of feedback, a research sweep you run before every roadmap sync, each runs the same way every time and anyone who clones the repo gets it.

9Cost, limits and the dials

"A workflow spawns many agents, so a single run can use meaningfully more tokens than working through the same task in conversation. Runs count toward your plan's usage and rate limits."Workflows doc, Cost
DIAL 1

Size guideline

Set in /config or /config workflowSizeGuideline=small. "Claude Code sends the guideline to Claude as advice, not a cap".

smallFewer than 5 agents
mediumFewer than 10 agents
largeFewer than 50 agents
unrestrictedNo guideline

"The default is medium, or small when you're signed in on a Pro plan".

DIAL 2

Try a slice first

"To gauge the spend before committing to a large task, run the workflow on a small slice first: one directory instead of the whole repo, or a narrow question instead of a broad one."

The Large workflow warning appears "When a workflow schedules more than 25 agents, or its projected token total passes 1.5 million". It is advisory, it does not stop the run.

DIAL 3

Model per stage

"Ask Claude to use a smaller model for stages that don't need the strongest one when you describe the task." Readers on Sonnet, verifiers on the strongest model, is a reasonable default for the churn run.

Agents in a fan-out share a prompt cache when they match on model, effort, agent type, tools, schema and working directory. Mixing models across a fan-out loses that.

The limits, verbatim from the docs

ConstraintWhy
No mid-run user input"For sign-off between stages, run each stage as its own workflow"
Up to 16 concurrent agents, fewer with fewer CPUs"Bounds local resource use"
Up to 4,096 items in one fan-out step"A silent cap would drop part of the workload without telling the script"
1,000 agents total per run"Prevents runaway loops"

Resume, and the usage limit

"Resume a paused run from /workflows by selecting it and pressing p." On relaunch, "Claude Code replays the run in the order agents started": completed agents return their saved result, and "The first agent whose prompt differs from the previous run, because you edited the script or an earlier agent returned something different, runs again, and so does every agent after it".

If an agent hits your claude.ai usage limit, "the run pauses rather than failing that agent: the agents that hit the limit wait for the reset, and no new agents start." It waits at most twice, then the agent fails.

To switch workflows off: toggle Dynamic workflows in /config, or "disableWorkflows": true in settings, or CLAUDE_CODE_DISABLE_WORKFLOWS=1.

10The workshop exercise

Same question the agents page ended on, "why are Pro users churning?", now as a workflow with a verify phase. One prompt, three phases, one saved command.

  1. Turn it on. Pro plan: /config, Dynamic workflows row, on. Everyone else already has it.
  2. Type the prompt.
    use a workflow to find why Pro users churn: read 07-user-interviews/,
06-user-feedback/ and 03-product-knowledge/competitive.md in parallel, keep only
drivers corroborated by 2 or more sources, then adversarially verify every
surviving driver against its source file before reporting. List refuted
drivers separately.
  3. At the approval prompt, choose View raw script. You are not reading code, you are reading the plan: find the three phase names, Read, Corroborate, Verify, and check the verify phase is there. Then Yes.
  4. Open /workflows while it runs. Drill into one Verify agent. Read its prompt. Note its token count.
  5. Read the report. Count the citations. Find the refuted list. Put it next to the plain-chat answer from the start of the agents session.
  6. Press s, save to .claude/workflows/ as churn-triangulate. Open the file in your editor.
  7. Rerun with different input. Run /churn-triangulate on why Free users do not convert to Pro. Same script, new args.
Done means: a report with file-and-line citations and a separate refuted list, a .js file in .claude/workflows/, and a second run from the saved command with a different question. A run that finished is not done. A run you can rerun tomorrow is.

11Where it breaks

BREAK 1

Wrong tool for the size

Three files and a summary is a subagent job. A workflow for it costs more and returns later. The docs' own line: reach for one "when a task needs more agents than one conversation can coordinate". Use the table in section 2.

BREAK 2

Approving without reading

The first time, click View raw script. If the plan has no verify phase and you asked for one, fix the prompt with Tab before it runs. A workflow you did not read is a fan-out you did not design.

BREAK 3

Permission prompts every minute

Every agent in the run obeys your permission rules. Add Read, Glob and whatever else the readers need to your allow rules before a long run, or the run stalls on the first prompt while you are in another window.

BREAK 4

Expecting a check-in mid-run

"No mid-run user input". If you want to approve stage 2 before it starts, "run each stage as its own workflow". Two saved commands, run in sequence.

BREAK 5

Editing the saved file by hand

The saved command is a script with rules about its first lines. Change it by hand and the /name command can vanish from autocomplete. Ask Claude to make the change instead, after loading /workflow-authoring, then /reload-skills.

BREAK 6

Trusting the report as proof

The verify phase reduces the risk, it does not remove it. A verifier is one more agent, and the docs note that when a verifier cannot check a claim "the report lists that claim as unverified instead of counting it as refuted." Open one source file yourself. Every time.
